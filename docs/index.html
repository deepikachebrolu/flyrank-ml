Abstract

This capstone asks whether observable content and search-performance signals can support a transparent, human-reviewed workflow for prioritizing pages for investigation. The CTR prediction experiment compares a median baseline with a Random Forest using a client-grouped holdout design. The recorded evaluation does not establish that the Random Forest outperforms the baseline. The action playbook therefore uses explicit rules to flag pages for review instead of presenting model scores as expected uplift. This is a decision-support prototype, not an autonomous content optimizer.

Reading the results: a high-priority item means “investigate earlier,” not “edit immediately.” No edits are automated, and the priority score is neither a probability nor a prediction of CTR uplift.

1. Research question

Can observable content and search-performance signals support a transparent, human-reviewed prioritization system for identifying pages that deserve further investigation?

Content teams have limited time to inspect every page. The intended decision is where to direct human review. This project does not claim to prove how search ranking works, guarantee ranking changes, or estimate the causal effect of editing a page.

2. Data and leakage controls

The working dataset is data/raw/content_refresh_anonymized.csv. The project notes record 30,000 rows, 44 columns, and 32 pseudonymized clients.

Feature handling

  • client_id is used for grouped validation, not as a predictive feature.
  • content_id is an identifier, not a predictive feature.
  • ctr is the target and must not be an input feature.
  • clicks_90d, trend-derived fields, and label-derived fields are excluded from the documented feature vector.
  • Remaining features still require timestamp/window checks. Grouped validation alone does not prove temporal safety.
Privacy: this public paper shows aggregate counts and an illustrative demo. It does not publish the row-level ranked queue or pseudonymous content/client records.

3. Methodology

Prediction experiment

The validation notebook describes a GroupShuffleSplit grouped by client, with random seed 42 and a 20% test fraction. The median baseline predicts the training-set median CTR. A Random Forest is evaluated on the same held-out records using MAE, RMSE, and R².

Action playbook

Because predictive superiority was not established, the playbook uses a transparent rule-based priority index. Rules use signals such as high impressions with low CTR, visible positions, content age, and relative engagement. Weights order investigation candidates; they are not probabilities, expected uplift, or financial returns.

7. Limitations and responsible use

  • Historical associations do not show that refreshing or editing content causes better outcomes.
  • The Random Forest did not outperform the baseline in the metric version currently recorded in this paper.
  • CTR depends on search intent, query mix, position, result layout, brand recognition, and other factors.
  • Thresholds are relative to this dataset and may not transfer to another population.
  • Content age alone does not prove content decay.
  • Missing or noisy metrics can affect prioritization.
  • The playbook is not production-ready. No content changes are automated.

Monitoring and future work

Review thresholds when distributions shift; investigate missingness or schema changes; document post-action outcomes against a baseline; and revalidate before considering model-based ranking. Retraining should be considered only with representative new data, a stable target, verified feature timing, leakage controls, and demonstrated improvement over a simple baseline.
